# ACL estese

## COS’È

Una **ACL estesa** (*Extended Access Control List*) è una lista di regole che filtra il traffico di rete in modo più preciso rispetto a una ACL standard.

Può controllare:

* **protocollo**
* **IP sorgente**
* **IP destinazione**
* **porte** del servizio

Questa è la differenza fondamentale:
la ACL standard guarda solo la sorgente, mentre la ACL estesa può guardare anche la destinazione e il servizio usato.

---

## A COSA SERVE

Serve quando vuoi fare un filtro più fine, per esempio:

* bloccare un host verso una certa rete, ma non verso altre
* consentire solo un certo servizio, come HTTP
* bloccare altri servizi anche se la destinazione è la stessa

Questa maggiore precisione è il motivo per cui le ACL estese sono molto importanti.

---

## COME FUNZIONA

La sintassi base, nel tuo corso, è questa:

```bash
access-list 100-199 permit/deny protocollo ip_sorgente wildcard_sorgente ip_destinazione wildcard_destinazione
```

Le ACL estese numerate usano, nei tuoi esempi, l’intervallo **100-199**.

### Ordine delle regole

Anche qui vale la regola fondamentale:

1. il router controlla la prima regola
2. poi la seconda
3. poi la terza
4. appena trova una corrispondenza, applica l’azione e si ferma

Se nessuna regola corrisponde, vale il **deny implicito finale**.

Per questo, spesso bisogna aggiungere una regola esplicita di permesso per il resto del traffico, ad esempio:

```bash
access-list 100 permit ip any any
```

# 1) Video 17: bloccare PC 2.3 verso la rete verde, ma lasciare passare verso la rete azzurra

## OBIETTIVO

Il PC `192.168.2.3`:

* **non deve accedere alla rete verde**
* ma **deve poter accedere alle altre reti**, per esempio alla rete azzurra

Questa è proprio la situazione in cui la ACL estesa è più utile della standard.

---

## COMANDI

### 1. Creo la ACL estesa

```bash
Router(config)# access-list 100 deny ip 192.168.2.3 0.0.0.0 192.168.1.0 0.0.0.255
Router(config)# access-list 100 permit ip any any
```

### 2. Applico la ACL all’interfaccia

```bash
Router(config)# interface Gig0/0
Router(config-if)# ip access-group 100 in
```

---

## SPIEGAZIONE DEI COMANDI

### Prima regola

```bash
access-list 100 deny ip 192.168.2.3 0.0.0.0 192.168.1.0 0.0.0.255
```

Significa:

* **deny** → blocca
* **ip** → il protocollo è IP
* **192.168.2.3 0.0.0.0** → sorgente precisa, solo quel PC
* **192.168.1.0 0.0.0.255** → destinazione, cioè tutta la rete verde

Quindi la regola dice:

> blocca i pacchetti che partono da `192.168.2.3` e vanno alla rete verde `192.168.1.0/24`

### Seconda regola

```bash
access-list 100 permit ip any any
```

Significa:

* consenti tutto il resto del traffico IP

Questa regola è necessaria perché, nelle ACL Cisco, il comportamento finale è comunque un blocco implicito per ciò che non è stato permesso.

---

## PERCHÉ QUESTA VOLTA POSSO METTERLA VICINO ALLA SORGENTE

Questo è il punto chiave del video.

Con le ACL standard, siccome controllano solo la sorgente, conviene metterle vicino alla destinazione.

Con le ACL estese, invece, posso specificare anche:

* chi parte
* dove va
* quale protocollo usa

Quindi posso bloccare subito il traffico inutile **vicino alla sorgente**, senza farlo attraversare tutta la rete.

### Mini schema logico

* traffico verso la rete verde → blocco
* traffico verso la rete azzurra → passa

---

## PERCHÉ L’INTERFACCIA È `IN`

Nel tuo esempio:

```bash
ip access-group 100 in
```

Si usa `in` perché, visto **dal router**, il traffico arriva nella porta `Gig0/0` dalla rete sorgente.

Quindi:

* il pacchetto **entra** nel router da quell’interfaccia
* per questo la ACL è **inbound**

---

## RISULTATO DEL VIDEO 17

* `192.168.2.3` **non può** raggiungere la rete verde
* però può raggiungere la rete azzurra
* perché la ACL estesa distingue la destinazione

Questo è proprio il vantaggio rispetto alla ACL standard.

# 2) Video 18: bloccare la rete rosa verso la rete verde, ma permettere il server web sulla porta 80

## OBIETTIVO

La rete rosa:

* **non deve accedere alla rete verde**
* **ma deve poter accedere al server verde solo sul servizio web**
* inoltre l’accesso alla rete azzurra deve essere consentito

Questa è una situazione perfetta per una ACL estesa, perché vogliamo filtrare non solo per rete, ma anche per **servizio**.

---

## COMANDI

### 1. Creo la ACL estesa

```bash
Router(config)# access-list 100 permit tcp 192.168.2.0 0.0.0.255 192.168.1.4 0.0.0.0 eq 80
Router(config)# access-list 100 permit ip 192.168.2.0 0.0.0.255 192.168.3.0 0.0.0.255
```

### 2. Applico la ACL all’interfaccia

```bash
Router(config)# interface Gig0/0
Router(config-if)# ip access-group 100 in
```

---

## SPIEGAZIONE DELLA PRIMA REGOLA

```bash
access-list 100 permit tcp 192.168.2.0 0.0.0.255 192.168.1.4 0.0.0.0 eq 80
```

Questa regola significa:

* **permit** → consenti
* **tcp** → il protocollo deve essere TCP
* **192.168.2.0 0.0.0.255** → tutta la rete rosa
* **192.168.1.4 0.0.0.0** → solo il server verde
* **eq 80** → solo la porta 80, cioè HTTP

Quindi il significato è:

> la rete rosa può raggiungere il server verde solo tramite il servizio web HTTP sulla porta 80

### Correzione importante

Nel tuo appunto c’era scritto `tep`: la forma corretta è **tcp**.

---

## SPIEGAZIONE DELLA SECONDA REGOLA

```bash
access-list 100 permit ip 192.168.2.0 0.0.0.255 192.168.3.0 0.0.0.255
```

Questa regola permette:

* tutto il traffico IP
* dalla rete rosa
* verso la rete azzurra

Quindi la rete rosa può accedere alla rete azzurra normalmente.

---

## COSA SUCCEDE IN PRATICA

La rete rosa:

* può accedere al server verde **solo** sul servizio HTTP
* non può fare altri accessi alla rete verde
* può comunque accedere alla rete azzurra

Quindi la ACL estesa ti permette di dire:

> “questo traffico sì, ma solo per questo servizio; tutto il resto no”

---

# 3) Perché la ACL estesa è più potente della standard

## DIFFERENZA CHIAVE

La ACL standard guarda solo:

* **IP sorgente**

La ACL estesa può guardare:

* **protocollo**
* **IP sorgente**
* **IP destinazione**
* **porta**

Quindi puoi fare regole molto più intelligenti.

### Esempio pratico

Con una ACL standard:

* blocchi un host intero

Con una ACL estesa:

* puoi bloccare solo quel host verso una certa rete
* oppure solo verso una certa porta
* oppure solo un certo protocollo

---

# 4) Perché si mette vicino alla sorgente

Questo è un altro punto molto importante.

Le ACL estese si mettono **vicino alla sorgente**, perché sono precise.

### Vantaggio

Blocchi il traffico indesiderato subito, senza farlo viaggiare inutilmente nella rete.

### Esempio

Se un host deve essere bloccato verso certi servizi, è inutile farlo arrivare fino alla rete di destinazione per poi rifiutarlo lì.

---

# 5) Inbound e outbound nelle ACL estese

Anche qui vale la distinzione:

* **in** = traffico che entra nell’interfaccia
* **out** = traffico che esce dall’interfaccia

Nel tuo esempio si usa:

```bash
ip access-group 100 in
```

perché il traffico entra nel router dalla parte della rete sorgente.

---

# 6) Porta 80 e servizio HTTP

Nel video 18 compare:

```bash
eq 80
```

Questo significa:

* controlla la porta 80
* quindi il servizio HTTP

### Importante da ricordare

L’ACL estesa non blocca solo indirizzi: può bloccare anche **servizi specifici**.

Questa è una delle sue funzioni più importanti.

# 8) Differenze importanti da ricordare all’orale

* **ACL standard** → controlla solo la sorgente
* **ACL estesa** → controlla sorgente, destinazione, protocollo e porte
* **standard** → vicino alla destinazione
* **estesa** → vicino alla sorgente
* **`permit ip any any`** → consente il resto del traffico IP
* **`eq 80`** → porta 80, quindi HTTP
* **`tcp`** → protocollo usato per quel servizio

* Che differenza c’è tra **ACL standard e ACL estesa**?
* Perché una **ACL estesa** si mette vicino alla sorgente?
* Cosa significa `eq 80` in una ACL estesa?
* Come si blocca un host solo verso una certa rete?
* Perché nelle ACL Cisco conta molto l’ordine delle regole?

---

[CONTROLLO STUDIO]

* ✔ Corretto: ACL estesa su intervallo 100-199, controllo di protocollo, sorgente, destinazione e porte, esempio con blocco di un host verso una rete, esempio con permesso TCP sulla porta 80, applicazione `in` su interfaccia vicina alla sorgente.
* ⚠ Correzioni: `tep` va corretto in `tcp`; `permit ip any any` non è una policy di default, ma una regola esplicita per consentire il resto del traffico; la ACL estesa va posizionata vicino alla sorgente proprio perché è più precisa.
* ➕ Integrazioni utili: significato di `eq 80`, differenza tra bloccare rete intera e bloccare solo un servizio, relazione tra ACL e servizi applicativi.
* ❌ Non trattato: ACL named estese, range di porte, esempi con `udp`, `icmp`, `gt`, `lt`, e casi avanzati di DMZ.

[DA RICORDARE]

* concetto chiave: la ACL estesa è più precisa perché filtra non solo per IP ma anche per protocollo e porta.
* errore comune: confondere `tcp` con `ip` o mettere la ACL estesa nel punto sbagliato della rete.
* collegamento utile: con le ACL estese puoi bloccare un traffico specifico senza bloccare tutto l’host, quindi sono fondamentali per il controllo fine dei servizi.

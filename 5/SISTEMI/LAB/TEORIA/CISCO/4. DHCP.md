# DHCP: spiegazione chiara e completa

Il **DHCP** è l’acronimo di **Dynamic Host Configuration Protocol**.  
Serve ad assegnare in modo **automatico e dinamico** i parametri di rete ai dispositivi client, senza che l’utente debba configurarli a mano.

In pratica, quando un PC, un laptop o un altro host si collega alla rete, può ricevere dal DHCP server:

- **indirizzo IP**
    
- **subnet mask**
    
- **default gateway**
    
- **eventuale DNS**
    

Questo evita errori di configurazione e rende più semplice la gestione di reti con molti dispositivi.

---

## 1) Come funziona il DHCP: le 4 fasi fondamentali

Il processo classico si chiama spesso **DORA**:

### 1. Discover

Il client, appena acceso o appena avviata la connessione di rete, **non ha ancora un IP**.  
Allora manda un messaggio di **richiesta in broadcast** per chiedere se in rete c’è un server DHCP disponibile.

### 2. Offer

Il server DHCP risponde con una **offerta**: propone un indirizzo IP e gli altri parametri di rete.

### 3. Request

Il client riceve anche più offerte, se ci sono più server, e **sceglie una sola offerta**.  
Quindi manda una richiesta di conferma al server scelto.

### 4. Acknowledge (ACK)

Il server conferma definitivamente l’assegnazione: quell’indirizzo è riservato a quel client per il tempo stabilito.

# 2) Esempio pratico in Cisco Packet Tracer: router come DHCP server

Nel video si usa un **router come server DHCP**.

## Configurazione logica

Il router ha l’interfaccia verso la LAN con indirizzo:

```bash
192.168.10.1 /24
```

Questa sarà la porta del router usata come **default gateway** dai client.

### Comandi corretti

Una configurazione tipica è questa:

```bash
enable
configure terminal

interface fastethernet0/0

 no shutdown
exit

ip dhcp excluded-address 192.168.10.1 192.168.10.10

ip dhcp pool POOLROUTER
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
exit
```

## 3) Correzioni importanti sui tuoi appunti

Nei comandi che hai scritto ci sono alcuni punti da sistemare:

### Errore 1: network

Hai scritto:

```bash
network 192.168.19.1 255.255.255.0
```

Questo è **sbagliato** se la rete è `192.168.10.0/24`.  
Nel comando `network` si indica la **rete**, quindi:

```bash
network 192.168.10.0 255.255.255.0
```

### Errore 2: indirizzo escluso

Hai scritto:

```bash
ip dhcp exclude 102.168.10.1 192.168.10.10
```

Qui ci sono due problemi:

- deve essere `ip dhcp excluded-address`
    
- `102.168.10.1` è un errore di digitazione, deve essere `192.168.10.1`
    

Comando corretto:

```bash
ip dhcp excluded-address 192.168.10.1 192.168.10.10
```

### Significato dell’esclusione

Con questa esclusione dici al router di **non assegnare automaticamente** gli indirizzi da `192.168.10.1` a `192.168.10.10`, perché possono essere usati per:

- router
    
- stampanti
    
- server
    
- dispositivi con IP statico
    

Così il primo indirizzo assegnato dinamicamente sarà **192.168.10.11**.

---

# 4) Perché il primo indirizzo assegnato diventa 11?

Perché gli indirizzi da `1` a `10` sono stati esclusi dal pool DHCP.  
Quindi il server, quando deve scegliere un IP libero, salta quelli riservati e assegna il primo disponibile, cioè:

```bash
192.168.10.11
```

Questo è esattamente quello che si vede nel video.

# 5) Spiegazione dei pacchetti PDU del DHCP

Qui c’è la parte più importante per capire davvero cosa succede.

## DHCP usa UDP, non TCP

DHCP funziona a livello di trasporto tramite **UDP**.

Le porte usate sono le cosiddette **well-known ports**, cioè porte standard e note del protocollo:

- **porta 67** → server DHCP
    
- **porta 68** → client DHCP
    

Le well-known ports sono le porte da **0 a 1023**, riservate ai servizi più importanti.

---

## Pacchetto 1: Discover

Il client non ha ancora un IP, quindi:

- **IP sorgente:** `0.0.0.0`
    
- **IP destinazione:** `255.255.255.255`  
    perché non sa ancora chi è il server e manda in broadcast
    
- **porta sorgente UDP:** `68`
    
- **porta destinazione UDP:** `67`
    

### Perché 0.0.0.0?

Perché il client **non ha ancora un indirizzo IP assegnato**.  
Quindi usa `0.0.0.0` come indirizzo sorgente provvisorio.

### Perché 255.255.255.255?

Perché è un **broadcast limitato**: il messaggio viene inviato a tutti gli host della rete locale.

### A livello di frame

Anche a livello 2 il frame è broadcast:

- **MAC sorgente:** MAC del client
    
- **MAC destinazione:** `FF:FF:FF:FF:FF:FF`
    

---

## Pacchetto 2: Offer

Il server risponde con un’offerta.

- **IP sorgente:** IP del server/router, per esempio `192.168.10.1`
    
- **IP destinazione:** spesso ancora broadcast, perché il client non è ancora configurato in modo definitivo
    
- **porta sorgente UDP:** `67`
    
- **porta destinazione UDP:** `68`
    

Il server propone:

- un IP disponibile
    
- subnet mask
    
- default gateway
    
- altri parametri
    

Nel tuo esempio il server può offrire, per esempio:

```bash
192.168.10.11
```

---

## Pacchetto 3: Request

Il client sceglie una proposta e manda una richiesta di conferma.

Anche questa richiesta è spesso inviata in **broadcast**, perché:

- potrebbe esserci più di un server DHCP
    
- tutti i server devono capire quale offerta è stata accettata
    

Quindi il client dice in pratica:

> “Accetto l’offerta di quel server e voglio proprio quell’indirizzo.”

---

## Pacchetto 4: Acknowledge

Il server risponde con l’**ACK**:

> “Ok, quell’indirizzo è tuo.”

Da questo momento il client può usare stabilmente:

- IP assegnato
    
- subnet mask
    
- gateway
    
- eventuale DNS

# 7) Collegamento con la teoria di rete

Questa parte è molto importante da dire all’esame:

- DHCP è un protocollo di **configurazione automatica**
    
- funziona in **client-server**
    
- usa **UDP**
    
- usa **broadcast** nella fase iniziale
    
- è utile nelle reti grandi perché evita configurazioni manuali
    
- riduce errori e velocizza la gestione degli host

# 8) Caso pratico: router o server?

Nel video si dice che si può fare sia con:

- **router come DHCP server**
    
- **server dedicato come DHCP server**
    

## Router come server

È comodo nei laboratori e nelle piccole reti.

## Server dedicato

È più realistico nelle reti più grandi, dove il DHCP è gestito da un server vero e proprio.

---

# 9) Nota utile per la maturità: se il server DHCP è su un’altra rete

Se il server DHCP non è nella stessa LAN del client, il broadcast non basta, perché il broadcast non attraversa i router.

In quel caso serve un **DHCP relay**, cioè sul router si usa spesso il comando:

```bash
ip helper-address
```

Questa è un’integrazione importante da sapere, anche se nei tuoi video non sembra essere il caso principale.

---

# 10) Riassunto super chiaro da ripetere all’esame

Il DHCP serve ad assegnare automaticamente gli indirizzi IP e i parametri di rete.  
Il client, quando si avvia, non ha ancora un IP, quindi manda un messaggio broadcast chiamato **Discover**.  
Il server risponde con un’**Offer**, il client manda una **Request** per accettare l’offerta, e il server conclude con un **ACK**.  
In Cisco Packet Tracer si può configurare un router come DHCP server creando un **pool**, indicando la **network**, il **default-router** e gli indirizzi da escludere con **excluded-address**.  
Nei pacchetti DHCP il client iniziale usa `0.0.0.0` come IP sorgente e `255.255.255.255` come destinazione, perché non conosce ancora il proprio indirizzo né quello del server.
